ADR-SAG-0017 First release surfaces

ADR · sc-agent · Approved · version 0.4.0

Context

Phase A ships libraries, the **decidr** decision CLI, the **sitr** tree-sitter CLI, and one Python wheel. Release must use one manifest-driven kit across five consumer channels. The problem is that every channel must release from the same tag, and per-channel workflow literals for crate lists or binary names would let the channels list different crates or binaries.

Decision

Phase A first release surfaces are **crates.io** (the crates listed in `release/publish-artifacts.toml`), **PyPI** (the `sc-decidr` wheel, holding the decidr and sitr APIs), **Homebrew**, **Scoop**, and **WinGet** (archives containing **decidr** and **sitr**), plus GitHub Release assets from the same tag. Sprints **a-11** (kit install) and **a-12** (dry-run) close the publish requirements; production uploads wait for owner dispatch.

Key principles

  • Customer-facing CLI names on channels are **decidr** and **sitr**.
  • The PyPI distribution name is **sc-decidr**.
  • No ad-hoc per-channel workflow literals for crate lists or binary names.

Rationale

- One manifest-driven kit drives all five consumer channels from the same tag. Owner ruling 2026-11-21: records follow docs/plans/reduction-plan.md.

Positive consequences

One tag drives every channel from `release/publish-artifacts.toml`.

Negative consequences

Workspace `Cargo.toml` must list members literally for kit validation.
