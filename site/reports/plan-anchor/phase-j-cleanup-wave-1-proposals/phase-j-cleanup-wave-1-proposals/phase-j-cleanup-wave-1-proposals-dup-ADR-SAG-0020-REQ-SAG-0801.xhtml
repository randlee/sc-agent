ADR-SAG-0020 Configuration has a shared scope and one scope per CLI, each global and per worktree

Decision

Configuration has two kinds of scope and two locations. - The shared scope is the file `sc-agent.json`. It holds shared defaults for configuration-reading CLIs: the project/phase (ADR-SAG-0021), worker count, and optional local-runner settings. A CLI file may override those defaults. - Each CLI that reads configuration has its own scope, the file `<cli>.json` named after the CLI: `decidr.json`, and the same pattern for every CLI added later. `sitr` reads no configuration. - The global location is `~/.sc-agent/`, the user's home directory joined with `.sc-agent` on every platform, or the folder named by nonempty `SC_AGENT_HOME`. An explicit configuration directory takes precedence. - The local location is `<worktree>/.sc/sc-agent/`, where `<worktree>` is the root of the git work tree the CLI runs in. It holds the same file names with the same keys. The CLIs and the files each one reads are these: | CLI | Global files | Local files | Environment prefix | |---|---|---|---| | `decidr` | `~/.sc-agent/decidr.local.json`, `~/.sc-agent/decidr.json`, `~/.sc-agent/sc-agent.json` | `<worktree>/.sc/sc-agent/decidr.local.json`, `<worktree>/.sc/sc-agent/decidr.json`, `<worktree>/.sc/sc-agent/sc-agent.json` | `DECIDR_`, plus `SC_PROJECT` | | `sitr` | none | none | none | Every CLI has a row, and every cell is filled; a CLI that reads no file of a kind says `none`. The table is updated when a CLI is added. A setting is looked up in nine layers, and the first layer that sets it wins: 1. the CLI flag; 2. the environment variable; 3. the local `<cli>.local.json`; 4. the local `<cli>.json`; 5. the local `sc-agent.json`; 6. the global `<cli>.local.json`; 7. the global `<cli>.json`; 8. the global `sc-agent.json`; 9. the built-in default, or a typed error when the setting is required and has no default. Model entries, `models.<alias>`, are set only in configuration files, layers 3 to 8: each is a structured row (`provider` and `id` strings, `released` a `YYYY-MM-DD` date) that a flag or flat environment variable cannot express. `<alias>` becomes the row's short name. A row's provider is one sc-agent already has, so configuration can add a model, including a local model on another computer, but cannot change where a paid API's key is sent. A local endpoint (laya and the two decider endpoints) is configured by `<endpoint>.host` and `<endpoint>.port`, such as `laya.host` and `laya.port`. Environment variables are named after the CLI: `DECIDR_<SETTING>`, with the parts of a nested key joined by a double underscore (`DECIDR_LAYA__PORT`). A setting with a wider audience than sc-agent may have its own name; the project/phase is `SC_PROJECT` (ADR-SAG-0021). Configuration files are JSON. TOML will be added when sc-config supports it (randlee/sc-runtime#152).

REQ-SAG-0801 Local decision runners come from configuration

Statements

  • Each local decision runner's network address MUST come from configuration.
  • Each local decision runner's model MUST have a fixed model id in the model table.
  • A selection of `decider` MUST resolve to the 4b decider model.
  • Each local decision runner MUST be selectable by its name wherever a decision model is selected.
  • `sc-agent` MUST send requests to a local decision runner in the Jev API format.
  • Configuration MUST be able to add a local model that runs on another computer.
  • `sc-agent` MUST NOT hard-code the network address of any local decision runner.
  • Configuration MUST NOT change where a paid API's key is sent.
