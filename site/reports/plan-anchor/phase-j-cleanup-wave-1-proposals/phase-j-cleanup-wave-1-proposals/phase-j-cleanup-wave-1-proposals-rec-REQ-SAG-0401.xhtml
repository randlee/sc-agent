REQ-SAG-0401 Credential resolution order and keyring defaults

REQ · sc-agent · Approved · version 0.6.0

Statements

  • `sc-agent` MUST resolve a key from the sources in the resolution order.
  • `sc-agent` MUST use the credential from the first source in the resolution order in which the credential is present.
  • The keyring service MUST be that provider's credential-variable name.
  • The keyring account MUST be the current OS account.

Requirement

Definitions: A *provider* is an endpoint that serves a model; a provider that names a credential-variable name has a key that `sc-agent` resolves, and a keyless provider (a local model) has none. A *credential* is the API key for one provider. A *credential-variable name* is the name of the environment variable that holds a provider's credential. The *keyring service* and the *keyring account* are the two components that identify a provider's entry in the platform keyring. The *resolution order* is the process environment, then the repository-root `.env` file, then the platform keyring (the OS credential store: Keychain on macOS, Credential Manager on Windows, Secret Service on Linux). A credential is *present* in a source when the source holds a value under the provider's credential-variable name; a blank platform-keyring value counts as absent. The *current OS account* is the user name of the operating-system user running the process.

Rationale

Credential handling stays in one place, so redaction and key lookup cannot disagree about which variables hold secrets. Owner ruling (2026-11-20), Rand Lee: "Keyring is super basic." Owner ruling (2026-11-20), Rand Lee: "Isn't ENV > .env > keyring (or win/linux equivalent) standard order?" A variable already set in the environment wins over `.env`, which is also dotenvy's default. Owner ruling (2026-11-21), Rand Lee: "Keyring is super basic." Owner ruling 2026-11-21: records follow docs/plans/reduction-plan.md.

Acceptance criteria

With a valid key in the environment, a different valid key in the repository-root `.env` and another in the keyring, the environment key is used; with none in the environment, the `.env` key is used; with neither, the keyring key is used.
