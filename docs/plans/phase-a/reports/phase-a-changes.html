## 4. Digest (REQ-SAG-0202)
For each question id `q`, in request order, the digest input is the compact JSON (serde_json, preserve_order) of
```json
{"body": {"model":…, "state":…, "questions": {"q": <question q>}, "assets":…},
"long_context": <bool>,
"parts": [{"name":…, "format":…, "sha256": <sc-sha hex of the lowercase hex of the bytes>}]}
```
hashed with `QuestionDigest::of_text`. The information is model, state, assets, every image part and the long-context header; the single question is `{q: question}`. Other questions are excluded. The images header is derived from the body, so it is covered. sc-sha hashes UTF-8 text only, so part bytes are hex-encoded and hashed once per part. Only sc-sha computes SHA-256.

What the crate is: a sync HTTP layer with no queue. It owns `HttpRequest`/`HttpResponse` (byte bodies, so multipart works), sends one request once (`Transport`), classifies the reply (busy / quota / final), and for a busy reply returns a not-before `Instant` for the resend under `ResendPolicy`. It never waits and takes no `CancelToken`: the holdoff wait and cancellation live in the caller's queue (the runner, A-9, uses `CancelToken::wait_until` and `on_cancel`). Every final reply that is neither busy nor quota is returned to the caller as `Next::Done(HttpResponse)`, whatever its status, so the backend decodes the API's own error bodies (Jev 400/422 are sc-decision-schema types; LLM providers' errors are read by sc-llm-provider with `ProviderReply::read`).
Main departures from the old crate:
- Old `retry.rs:247-268` (`Hooks::wait`, `thread::sleep` slices) and `retry_loop` (507-626) are not copied; `send_once` returns `Next::ResendAt(instant)`.
- Old `MAX_SENDS = 5` cap and `clamp(1, MAX_SENDS)` removed; `max_sends` is any `NonZeroU32`, default 5.

- Old `api_failure` status mapping is not copied: non-busy statuses go back to the backend.
- `HeaderName::new` and `Endpoint::loopback_http` panicked through `assert!`; both go.
- No `test-util` feature: tests drive `send_once` with an explicit clock and a scripted transport.
+ - A timed-out send is resent unchanged at once, counting toward `max_sends`; connect, DNS, TLS and other transport failures are returned after one send; every other remote error (402, Anthropic's usage-limit 400, 503, ...) is a final reply returned to the backend with the remote id and message (REQ-SAG-0601).

## Shape in one paragraph
`DecisionRunner` owns one `Arc<dyn Backend>` (A-2), one `HttpClient` (A-5: transport, `ResendPolicy`, general logger), a `SessionLogger` and a `GeneralLogger` (A-8), and implements `Decision`. `decide_stream` starts one feeder thread (pulls the caller's iterator into a bounded `JobQueue`) and `workers` worker threads (default 8, `AgentConfig.workers`). A worker takes a ready job; on its first attempt it computes the question digests and encodes the request once; it calls `HttpClient::send_once`. `Next::ResendAt(t)` puts the job back in the queue's held heap and frees the worker. `Next::Done(response)` goes to `backend.decode(response, &request)`; `Err(DecisionError::SchemaMismatch)` puts the job back as ready with freshthe same `Attempts` and the same encoded bytesbytes; whileevery fewersend thanof a request (busy, timeout and schema resends alike) counts against one `max_sends` repliesand haveone been90 decoded;s thebudget, replyand thatwhen reacheseither `max_sends`runs finishesout after a mismatch the job finishes with that `SchemaMismatch`, whose detail names what did not match (REQ-SAG-0901; decoded replies are counted apart from the busy and timeout sends of each reply, assistant decision);(REQ-SAG-0901); anything else finishes the job. Idle workers wait with `Condvar::wait_timeout` to the earliest holdoff end; a `CancelToken::on_cancel` hook (A-1) cancels the queue and wakes every waiter at once. Each finished job writes exactly one session row, then its `DecisionResult` goes to a bounded result queue that the returned iterator drains, so results come back fastest first. `decide` runs one request on the caller's thread and holds off with `CancelToken::wait_until`.
