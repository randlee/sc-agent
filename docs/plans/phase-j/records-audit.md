# Records audit against the owner's session-log data model (ruling 2026-11-24)

Read-only audit. Revisions read (after `git fetch origin`): sc-agent `origin/develop` 6b5e5ad, judge-jev `origin/develop` 0dd4719, plan-anchor `origin/develop` b55d927. The design is `~/github/sc-agent-worktrees/integrate/phase-j/docs/plans/phase-j/audit-trail-log-normalization-SQLite.md` at 0f72270.

The model is abbreviated M1 to M5 below:
- **M1**: every Jev query from every tool gets one session row, keyed by its ULID `session_id`. The log is not optional or configurable, and rows carry tool info.
- **M2**: tool records hold only derived information and reference `session_id`. They do not copy the query or the response.
- **M3**: a dry run writes no session row and no result record as if it were real.
- **M4**: a cache hit writes no new row and returns the `session_id` of the row that holds the result.
- **M5**: rows are written in Rust through sc-observability, 1 MiB per event including the wrapper. The largest request that fits is recorded whole. A larger one gets no row and a `log.session_write` error. The log is never rotated or pruned.
