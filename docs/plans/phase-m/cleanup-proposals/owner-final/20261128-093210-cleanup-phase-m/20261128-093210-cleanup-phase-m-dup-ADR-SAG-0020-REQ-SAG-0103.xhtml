ADR-SAG-0020 Configuration has a shared scope and one scope per CLI, each global and per worktree

Decision

Configuration has two kinds of scope and two locations. - The shared scope is the file `sc-agent.json`. It holds shared defaults for configuration-reading CLIs: the project/phase (ADR-SAG-0021), worker count, and optional local-runner settings. A CLI file may override those defaults. - Each CLI that reads configuration has its own scope, the file `<cli>.json` named after the CLI: `decidr.json`, and the same pattern for every CLI added later. `sitr` reads no configuration. - The global location is `~/.sc-agent/`, the user's home directory joined with `.sc-agent` on every platform, or the folder named by nonempty `SC_AGENT_HOME`. An explicit configuration directory takes precedence. - The local location is `<worktree>/.sc/sc-agent/`, where `<worktree>` is the root of the git work tree the CLI runs in. It holds the same file names with the same keys. The CLIs and the files each one reads are these: | CLI | Global files | Local files | Environment prefix | |---|---|---|---| | `decidr` | `~/.sc-agent/decidr.local.json`, `~/.sc-agent/decidr.json`, `~/.sc-agent/sc-agent.json` | `<worktree>/.sc/sc-agent/decidr.local.json`, `<worktree>/.sc/sc-agent/decidr.json`, `<worktree>/.sc/sc-agent/sc-agent.json` | `DECIDR_`, plus `SC_PROJECT` | | `sitr` | none | none | none | Every CLI has a row, and every cell is filled; a CLI that reads no file of a kind says `none`. The table is updated when a CLI is added. A setting is looked up in nine layers, and the first layer that sets it wins: 1. the CLI flag; 2. the environment variable; 3. the local `<cli>.local.json`; 4. the local `<cli>.json`; 5. the local `sc-agent.json`; 6. the global `<cli>.local.json`; 7. the global `<cli>.json`; 8. the global `sc-agent.json`; 9. the built-in default. Model entries, `models.<alias>`, are set only in configuration files, layers 3 to 8: each is a structured row (`provider` and `id` strings, `released` a `YYYY-MM-DD` date) that a flag or flat environment variable cannot express. `<alias>` becomes the row's short name. A row's provider is one sc-agent already has. Environment variables are named after the CLI: `DECIDR_<SETTING>`, with the parts of a nested key joined by a double underscore (`DECIDR_LAYA__PORT`). A setting with a wider audience than sc-agent may have its own name; the project/phase is `SC_PROJECT` (ADR-SAG-0021). Configuration files are JSON. TOML will be added when sc-config supports it (randlee/sc-runtime#152).

REQ-SAG-0103 Provider and model are separate

Statements

  • A model-table row MUST store its provider in a field separate from its model.
  • A request MUST carry the model id stored in the selected model-table row.
  • sc-agent MUST be able to send requests through Together.
  • sc-agent MUST be able to send requests through OpenRouter.
  • When configuration names a provider for a model, sc-agent MUST send that model's requests to that provider.
  • When no provider is configured for a model, sc-agent MUST prefer a provider that needs no key over one that needs a key.
  • When no provider is configured for a model and every provider serving it needs a key, sc-agent MUST use the first of them whose key is found.
  • The provider that sends requests to the OpenAI API MUST have the name `openai`.
  • A short name MUST NOT encode its provider.
  • A request MUST NOT require the caller to name a provider.
